# UI Guidelines: shadcn/ui + Tailwind CSS v4 + Ant Design 6.x 混合使用规范

> **这是一份协议，不是某个产品的文档。** 只写终态规则，不含任何产品的实现现状、迁移计划、审计数据或修订记录。
> 本文件只写**框架相关规则**。样式书写（C1–C10）、颜色/间距/字号、按钮系统、表单、容器、弹窗、图标、动效、交互复用等**框架无关的基础规范**见 [`00.base.md`](./00.base.md)，本文件直接引用，不重复。
> 违反以下规则视为错误，必须在提交前修正。

三者不是自由选择关系，而是按控制权分层使用，并通过 MCP 在生成代码前强制查证实时 API。

## 1. MCP 前置查证（强制，先于任何 UI 代码生成）

**核心原则**：Agent 不得凭训练数据中的记忆生成 Ant Design 或 ProComponents 代码。
生成任何 UI 代码前，必须先通过 MCP 查证当前版本的 API、示例和变更日志。

### 1.1 Ant Design 官方 MCP（强制启用）

从 @ant-design/cli v6.3.5 起，可通过 `antd mcp` 启动官方 MCP 服务器，提供 8 个工具和 2 个提示词。

| 工具 | 用途 | 使用时机 |
|---|---|---|
| antd_list | 列出可用组件 | 不确定组件是否存在时 |
| antd_info | 获取组件属性规格 | 写任何 antd 组件前 |
| antd_doc | 获取完整文档 | 需要确认用法和约束时 |
| antd_demo | 获取可运行代码示例 | 需要参考标准写法时 |
| antd_token | 查询 Design Token 值 | 做主题桥接或样式覆盖时 |
| antd_design_md | 获取设计语言文档 | 需要理解设计意图时 |
| antd_semantic | 查看 DOM 结构和样式钩子 | 调试样式覆盖问题时 |
| antd_changelog | 分析跨版本 API 变更 | 疑似 API 已弃用或迁移时 |

**提示词**：`antd-expert` 将 Agent 锚定为 Ant Design 专家；`antd-page-generator` 辅助页面级生成。

```json
{
  "mcpServers": {
    "antd": {
      "command": "npx",
      "args": ["-y", "@ant-design/cli", "mcp"]
    }
  }
}
```

已全局安装 CLI 时可直接使用 `antd mcp`，也可通过 `antd setup --client cursor|claude|vscode|codex` 写入配置。

### 1.2 shadcn MCP（推荐启用）

shadcn CLI 内置官方 MCP，可浏览、搜索并安装 registry 中的组件，支持默认 registry、第三方与私有 registry。

- 需要新增 shadcn 组件时，先通过 MCP 确认组件存在于 registry，再安装。
- 不得猜测组件名称，或手写一个"看起来像 shadcn"的非标准实现。
- shadcn 组件的源码就在仓库里，修改现有组件时直接读源码，无需经过 MCP。
- 项目配置（别名、框架、Tailwind 版本）用 `npx shadcn@latest info` 获取，没有 MCP 等价物。

### 1.3 ProComponents 社区 MCP（可选）

`@tony2026m/pro-components-mcp` 提供组件列表、文档、示例、更新日志与迁移指南。

```json
{
  "mcpServers": {
    "pro-components": {
      "command": "npx",
      "args": ["@tony2026m/pro-components-mcp"]
    }
  }
}
```

**重要标注**：社区维护，非官方。只作辅助参考，**不作版本真相源**；版本以 `package.json` 锁定值为准。

### 1.4 MCP 不可用时的降级策略

1. 优先用 Ant Design CLI 的离线能力：`antd doc`、`antd lint`、`antd changelog`。
2. 回退到 §4.5 废弃 API 清单与 §5 Token 桥接规则。
3. 既无 MCP 也无 CLI 时，**必须先询问用户**，不得凭记忆生成 antd 6 代码。

## 2. 分层规则（强制）

### 2.1 shadcn/ui + Tailwind：视觉叙事层

以下场景必须使用 shadcn/ui 组件与 Tailwind 工具类：

- 页面骨架：侧边栏、顶部导航、内容区容器
- 导航：菜单、标签页、面包屑、非表格内建的分页控件
- 原子交互：按钮、输入框、选择器、开关、滑块、复选框、单选框
- 反馈：Dialog、Sheet、Sonner（toast 已废弃）
- 空状态、错误状态、引导页
- 设置页面、服务卡片、密钥管理表单中不涉及复杂联动的部分
- 所有面向用户的"第一眼界面"

原则：用户能直接感知设计品质的地方，源码必须在自己仓库中。

**落地顺序（写新样式前必须自问）**

1. shadcn 有没有现成组件？有就装，用 Tailwind 类**覆盖**尺寸与配色，不改结构。
2. 需要覆盖的样式，能不能只在组件文件里加几个类解决？能就不要往 `index.css` 写。
3. 确实要写 CSS 时，先确认它属于哪一层（`base` / `components` / `overrides`），
   不要用 `!important`——层序本身就能解决优先级（见 `00.base.md` §1 C4/C5）。
4. 以上都不行，才自己做组件。

自研 CSS 的唯一正当理由是「覆盖组件做不出来的组合」，而不是「我没找到现成组件」。

### 2.2 Ant Design：功能引擎层

以下场景只允许使用 Ant Design，禁止用 shadcn 手写重实现：

- 数据表格：排序、筛选、分页、列配置、批量选择、可编辑单元格
- 复杂表单：多字段联动、动态增减字段、Schema 驱动校验、跨步骤表单
- 树形控件、级联选择、穿梭框
- 日期/时间范围选择器
- 上传组件（断点续传、文件列表管理）
- 虚拟滚动长列表

ProTable、ProForm、ProLayout 属此层，可优先于裸 antd 组件使用，版本策略见 §0。

### 2.3 禁止交叉

- 禁止用 shadcn `<Table>` 手写带筛选/排序/分页的数据表格。
- 禁止用 antd `<Button>` `<Card>` `<Modal>` 搭建主界面。
- 禁止在同一视觉区域内混用两套原子组件，且无明确容器边界。
- 禁止同时引入 MUI、Chakra、Mantine、HeroUI 等其他组件库。
- 禁止同时新增两套体系中的同类原子组件。

## 3. 样式隔离（Tailwind v4 配置，强制）

### 3.1 不再使用 tailwind.config.js 做插件配置

Tailwind v4 是 CSS-first 的，插件通过 `@plugin` 加载，不再使用 `require()` 或 `@import`：

```css
/* 样式入口 */
@import "tailwindcss/theme";
@import "tailwindcss/utilities";

@plugin "tailwindcss-scoped-preflight" {
  isolation-strategy: inside;
  selector: .tw-root;
  except: .ant-app;
}
```

- `.tw-root`：包裹所有 shadcn/Tailwind 内容的根容器 class。
- `.ant-app`：Ant Design 的根容器，被排除在 Preflight 影响之外。
- 必须用 `@import "tailwindcss/theme"` + `@import "tailwindcss/utilities"` 替代单一的
  `@import "tailwindcss"`，否则全局 preflight 会与 scoped preflight 冲突。

### 3.2 CSS 层叠顺序（@layer）

```css
@layer vendor, theme, base, components, utilities, overrides;

@import url("antd/dist/reset.css") layer(vendor);
@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/utilities" layer(utilities);
```

原则：**永远不要用 `!important` 覆盖 antd 样式**。覆盖不生效时，先查 `@layer` 顺序，再改用 ConfigProvider token。

### 3.3 禁止全局 Ant Design 选择器覆盖

```css
/* 禁止 */
.ant-btn { ... }
.ant-table-thead > tr > th { ... }
```

允许：用 ConfigProvider 的 `theme.token` / `theme.components` 调整，或使用限定作用域的 className。
Ant Design 6 持续优化内部 DOM 结构，依赖内部选择器的样式在补丁升级后可能失效——这是额外的工程理由。

## 4. Ant Design 6.x 导入与使用规范

### 4.1 样式入口

- 默认模式：`import 'antd/dist/reset.css'` 一次即可。
- `zeroRuntime` 模式（仅 SSR 或确认性能瓶颈由 antd 运行时样式引起时）：
  `theme={{ zeroRuntime: true }}` + `import 'antd/dist/antd.css'`。启用后动态主题切换不可用，默认不要开启。

### 4.2 Tree-shaking 与导入方式

Ant Design 6 默认支持基于 ES modules 的 tree shaking，不需要 babel-plugin-import，不需要子路径导入。

```tsx
// 正确
import { Table, Form, Select, DatePicker, Upload } from 'antd';

// 禁止
import Table from 'antd/es/table';
```

### 4.3 图标

```tsx
import { PlusOutlined, SearchOutlined } from '@ant-design/icons';
```

禁止 `import * as Icons from '@ant-design/icons'`。@ant-design/icons 必须用 6.x，与 antd@6 配套。
图标库风格与尺寸规则见 `00.base.md` §10。

### 4.4 反馈 API 必须通过 App.useApp()

```tsx
const { message, modal, notification } = App.useApp();
```

或 `Modal.useModal()`。静态方法（`message.xxx`、`Modal.confirm`）不读取 ConfigProvider 主题上下文。

### 4.5 Ant Design 6 废弃 API 清单（禁止生成）

以下 API 在 6.x 已弃用、将于 7.0 移除。Agent 应优先通过 `antd_changelog` / `antd_doc` 实时核实，本清单作降级兜底。

| 组件 / 场景 | 禁止写法 | 必须改为 |
|---|---|---|
| Alert | closeText / closeIcon / message | closable.closeIcon / title |
| AutoComplete / Select | dropdownMatchSelectWidth | popupMatchSelectWidth |
| 下拉浮层 | dropdownStyle / dropdownClassName / popupClassName / popupStyle | styles.popup.root / classNames.popup.root |
| 下拉浮层 | dropdownRender | popupRender |
| 下拉浮层 | onDropdownVisibleChange / onPopupVisibleChange | onOpenChange |
| AutoComplete | dataSource | options |
| Avatar | size="default" | size="medium" |
| Avatar.Group | maxCount / maxStyle / maxPopoverPlacement / maxPopoverTrigger | max={{ count, style, popover }} |
| Badge / Descriptions | size="default" / size="middle" | size="medium" / size="large" |
| Breadcrumb | routes / Breadcrumb.Item / breadcrumbName | items |
| Button.Group | Button.Group | Space.Compact |
| Button | iconPosition | iconPlacement |
| Card | headStyle / bodyStyle / bordered | styles.header / styles.body / variant |
| Cascader | showArrow | 默认行为；如需隐藏用 suffixIcon={null} |
| Collapse | destroyInactivePanel / expandIconPosition | destroyOnHidden / expandIconPlacement |
| DatePicker / RangePicker | dropdownClassName / popupClassName / popupStyle / bordered | classNames.popup.root / styles.popup.root / variant |
| Descriptions | labelStyle / contentStyle | styles.label / styles.content |
| Divider | type / orientationMargin | orientation / styles.content.margin |
| Drawer | headerStyle / bodyStyle / footerStyle / maskStyle / width / height / maskClosable | styles.* / size / mask.closable |

对某个 antd 6 API 不确定时，必须先查证或询问，不得凭 v5 记忆生成。

## 5. Design Token 统一（Ant Design 6 为单一真相源）

Ant Design 6 默认输出纯 CSS 变量，以其 CSS 变量作为项目颜色的单一来源。

### 5.1 在 ConfigProvider 中暴露 CSS 变量

```tsx
<ConfigProvider
  theme={{
    cssVar: { key: ':root' },
    token: {
      colorPrimary: 'var(--brand-primary)',
      borderRadius: 6,
      fontFamily: 'var(--font-sans)',
    },
  }}
>
  <App />
</ConfigProvider>
```

开启 `cssVar` 后，Ant Design 会生成 `--ant-color-primary`、`--ant-border-radius` 等全局 CSS 变量。

### 5.2 Tailwind v4 通过 @theme inline 桥接

`@theme inline` 把变量值直接内联进工具类，不额外发出自定义属性，是 shadcn 单主题 + 暗色切换的推荐用法。

```css
@theme inline {
  --color-primary: var(--ant-color-primary);
  --color-background: var(--ant-color-bg-container);
  --color-foreground: var(--ant-color-text);
  --color-border: var(--ant-color-border);
  --radius-DEFAULT: var(--ant-border-radius);
}
```

完成后 `bg-primary`、`text-foreground`、`border-border` 自动使用 antd 主题变量。

禁止在 Tailwind 工具类中硬编码颜色（如 `bg-[#1677ff]`）。

### 5.3 shadcn 的 CSS 变量与 Ant Design 对齐

shadcn 组件内部使用 `bg-background`、`text-foreground` 等语义类，必须把这些变量指向 `--ant-*`：

```css
:root {
  --background: var(--ant-color-bg-container);
  --foreground: var(--ant-color-text);
  --primary: var(--ant-color-primary);
  --border: var(--ant-color-border);
}
```

只允许一个方向：Ant Design → shadcn/Tailwind。不允许两套并行定义。

### 5.4 字号 token 生成

`00.base.md` §4 的 ten-step type scale 在 Tailwind 中通过 `@theme` 生成工具类，
不要直接写 `text-[13px]` 之类的任意值：

```css
@theme {
  --text-2xs: 9px;
  --text-xs: 10px;
  --text-sm: 12px;
  --text-base: 13px;
  --text-md: 14px;
  --text-lg: 16px;
  --text-xl: 20px;
  --text-2xl: 24px;
  --text-3xl: 30px;
  --text-4xl: 44px;
}
```

### 5.5 间距与圆角

- 间距直接用 Tailwind 默认步进（1 = 4px），不写 `p-[7px]`、`gap-[10px]`；规则见 `00.base.md` §3。
- 圆角只用 `00.base.md` §3 的四档，并映射到 token：控件 `rounded-sm`(4px) / 小标签 5px /
  卡片 `rounded-[10px]` / 浮层 `rounded-[14px]`。全仓圆角值不得超过 4 种。
- antd 侧同步用 `theme.token.borderRadius` 与 `theme.components` 表达同一套档位，避免两边视觉漂移。

## 6. shadcn 组件获取

- CLI 命令是 `shadcn`，不是 `shadcn-ui`：`npx shadcn@latest add <component>`。
- 新增组件前先通过 MCP 确认 registry 中存在，不得猜测名称或手写非标准实现。
- 组件安装后成为仓库源码，改样式直接改组件文件；不得在页面侧用大量覆盖类拼出另一个组件。
- 引入组件前先搜索仓库是否已有封装，禁止重复创建同功能组件。
- 组件内部的样式覆写仍受 `00.base.md` §1（C1–C10）约束。

## 7. 快速判定表

| 场景 | 选择 |
|---|---|
| 页面布局、侧边栏、导航 | shadcn + Tailwind |
| 设置页、开关、输入框 | shadcn + Tailwind |
| 数据表格（排序/筛选/分页） | Ant Design Table 或 ProTable |
| 多字段联动配置表单 | Ant Design Form 或 ProForm |
| 树形选择、级联选择 | Ant Design |
| 简单的卡片列表 | shadcn Card + Tailwind |
| 带批量操作的长列表 | Ant Design Table / ProTable |
| 确认/提示对话框 | shadcn Dialog / AlertDialog |
| 需要 Schema 校验的复杂对话框表单 | Ant Design Modal + Form |
| 全局消息提示 | `App.useApp()` 的 message（禁止静态调用） |
| Toast | shadcn Sonner（旧 toast 已废弃） |

## 8. 违反时的修正路径

1. **检查 MCP 使用**：未查证就生成了 antd 代码，触发一次 `antd_changelog` 或 `antd_info` 核实并修正。
2. **检查导入方式**：子路径导入改为根路径命名导入。
3. **检查废弃 API**：对照 §4.5，把 `dropdownClassName`、`visible`、`bordered`、`size="default"` 等改为 6.x 写法。
4. **检查样式隔离**：样式入口若只有 `@import "tailwindcss"`，改为 theme + utilities + `@plugin` 三件套。
5. **检查 Token 方向**：shadcn 的 `--primary` 与 antd 的 `--ant-color-primary` 若为两套独立值，
   把 `--primary` 改为 `var(--ant-color-primary)`。
6. **检查 toast**：从 shadcn 引入的 `toast` 替换为 sonner。
7. **检查 ProComponents 版本与 API 一致性**：按 `package.json` 锁定版本核对。
8. **检查 shadcn CLI 命名**：文档与脚本中不应再出现 `shadcn-ui` 命令。
9. **检查颜色硬编码**：搜索 `bg-[#`、`text-[#`、`style={{ color:`，改为语义类（详见 `00.base.md` §1 C6/C7）。
10. **检查基础规范**：间距网格、字号、泛选择器、`!important`、圆角档位、动效——
    逐条走 `00.base.md` §13 提交前自检。

## 9. Agent 行为约束（框架部分）

基础条款（间距网格、字号、可点击元素、按钮、CSS C1–C10、弹窗、动效）见 `00.base.md` §13。以下为本技术栈专属条款：

1. **MCP 优先**：生成任何 antd 或 ProComponents 代码前，先调用 `antd_info` / `antd_doc` / `antd_changelog`
   （或降级到 antd CLI）核实当前版本 API。禁止凭记忆生成。
2. **先判定归属**：视觉层 → shadcn + Tailwind；排序/筛选/分页/复杂联动 → Ant Design。无法判定时默认 shadcn。
3. **所有 antd 导入使用根路径命名导入**，禁止子路径导入，禁止 babel-plugin-import。
4. **修改 antd 样式时优先 ConfigProvider token**，其次限定作用域 className。禁止 `.ant-` 全局选择器与 `!important`。
5. **严格对照 §4.5 废弃清单**；清单未覆盖的 API 先查 MCP 或 CLI，不确定先问。
6. **Tailwind 工具类禁止硬编码颜色**，必须使用桥接后的语义类。
7. **使用 shadcn/Tailwind 的页面必须包含 `.tw-root` 包裹容器**；整页为 antd 功能层时根容器应为 `.ant-app`。
8. **禁止同时新增 shadcn 和 antd 的同类原子组件**。
9. **ProComponents 版本必须与 `package.json` 锁定版本一致**，禁止混用 2.x 与 3.x 写法。
10. **shadcn CLI 命令使用 `shadcn`**，新组件通过 `npx shadcn@latest add <component>` 添加。
11. **新增 shadcn 组件前先通过 MCP 确认 registry 中存在**，不得猜测名称或手写非标准实现。
